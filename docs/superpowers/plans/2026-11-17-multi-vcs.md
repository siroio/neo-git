# Multi-VCS Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for independent backend tasks and reviews. User instructions prohibit commits and worktree creation; work in the existing checkout.

**Goal:** Add native jj, Mercurial, SVN and Perforce operations while preserving Git behavior.

**Architecture:** Retain the mature Git implementation. Share process/layout/diff primitives with a new common non-Git UI and pure backend request builders.

**Tech Stack:** Emacs 29.1+ Elisp, ERT, git/jj/hg/svn/p4 CLIs.

**Spec:** `docs/superpowers/specs/2026-11-17-multi-vcs-design.md`

## Global Constraints

- Only `neo-git/`; no stage/commit/push/worktree or user configuration changes.
- Standard Elisp libraries; no Git feature removal or shortcut of existing checks.
- CLI commands use argument vectors, scoped paths and explicit mutation controls.
- Report real CLI integration separately from parser/request fixture tests.

## Review Focus

1. Filename metacharacters cannot become filesets, revision selectors or options: backend request tests.
2. Stale asynchronous responses cannot repaint after refresh/close: core lifecycle tests.
3. Pending multi-command writes survive q/kill-buffer and block another write: core lifecycle tests.
4. SVN/P4 commits affect a server; selection/confirmation cannot silently expand: backend/action tests.
5. Colocated jj/Git and existing Git single-file installation remain usable: detection/package tests.
